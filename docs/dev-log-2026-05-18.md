## 三、当前未提交修复

### 3.1 JSON 队列“清空”按钮修复

问题：

手机采集器录入外部链接后，自动提取出的项目信息进入 JSON 队列；其中部分名称或内容不准确，需要删除。但原“清空”按钮只取消勾选，不会删除队列记录。

修复：

- 新增 `deleteDiscoveryItems(ids)`，同时支持 DB-backed `DiscoveryCandidate` 队列和旧 JSON 文件队列
- 新增 `bulkDeleteDiscoveryItemsAction(ids)`
- 后台队列表格新增 `删除所选`
- 原 `清空` 改为 `取消选择`
- 删除前增加确认提示，说明不会删除已入库项目

涉及文件：

- `agents/discovery/discovery-store.ts`
- `app/admin/discovery/items/actions.ts`
- `app/admin/discovery/items/discovery-json-queue-table.tsx`

### 3.2 AI 认知卡环境变量兼容修复

问题：

项目编辑页点击“生成 AI 认知卡”时提示“AI 服务未配置，请检查服务器环境变量”。代码根因是认知卡生成链路只读取 `DEEPSEEK_API_KEY`，而系统其他 AI 链路已存在通用配置 `AI_PROVIDER`、`AI_MODEL`、`AI_API_KEY`、`AI_BASE_URL`。

修复：

- `getDeepSeekClient()` 兼容 `DEEPSEEK_API_KEY` 和 `AI_API_KEY`
- DeepSeek 专用 key 存在时默认使用 DeepSeek base URL
- 无 DeepSeek key 时回退到 `AI_BASE_URL` 或 OpenAI SDK 默认 endpoint
- 新增 `getDeepSeekCompatibleModel()`，让认知卡模型从 `DEEPSEEK_MODEL_INSIGHT` 回退到 `AI_MODEL` / `OPENAI_MODEL`
- 错误提示同时识别 `Missing DEEPSEEK_API_KEY` 和 `Missing AI_API_KEY`

涉及文件：

- `lib/deepseek.ts`
- `lib/project-ai-insight.ts`
- `app/api/admin/projects/[id]/ai-insight/route.ts`

注意：

部署环境仍必须至少配置一组可用 AI 凭据。可选方案：

- DeepSeek：`DEEPSEEK_API_KEY`，可选 `DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL_INSIGHT`
- 通用 OpenAI 兼容：`AI_API_KEY`、`AI_MODEL`，可选 `AI_BASE_URL`

### 6.3 手机采集自动提取准确率仍需运营复核

自动提取已经能减少手工复制，但外部文章里项目名称、摘要、官网来源仍可能误判。

当前处理方式：

- 错误候选可在 JSON 队列中删除
- 手机原始采集仍保留 source material
- 失败素材可重试

后续建议：

- 增加“提取结果预览/确认后入队”模式
- 对公众号文章中的项目名称增加二次校验
- 将失败原因和提取来源片段显示得更清楚

### 6.4 发现系统业务逻辑仍偏集中

`app/admin/discovery/items/actions.ts` 仍包含较多抓取、解析、入队、导入逻辑。随着 cron、API、后台按钮共用这些能力，继续放在页面 action 文件中会提高维护成本。

后续建议：

- 把 URL 抓取和文章项目提取迁移到 `lib/discovery/article-extraction.ts`
- 把通用项目入队逻辑迁移到 `lib/discovery/queue-projects.ts`
