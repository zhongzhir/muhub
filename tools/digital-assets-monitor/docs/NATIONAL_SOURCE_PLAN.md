# 全国数字资产处置信源建设与验收方案

更新时间：2026-09-05
状态：已接受范围纠正；全国目录建设启动；全国采集未完成。公共资源省级入口完成一轮批量审计，尚未正式接入。

## 1. 需求及当前结论

用户要求主动全网发现信源，不能以仓库材料涉及的机构限定范围。全国31省区市主要产权交易所、数据交易所、技术交易所及其主要市级机构均应纳入调查；公安机关覆盖省、市、县（区、旗）层级，不止公安部和省厅。法院、检察院、纪检监察、财政、公共资源交易、招投标、媒体及国际机构继续保留在总范围中。港澳合作与国际处置渠道另建区域维度。

monitor.muhub.cn 的服务、HTTPS、邀请码登录和证书续期测试已通过。生产首次扫描32源，15成功、17失败、0入库；只证明基础设施可用，不能视为监测产品验收完成。

## 2. 核心模型

机构表与渠道表分离。一个公安机构可通过独立官网、当地政府信息公开栏目、上级公安网站、官方账号多渠道发布；一个省级网站可能承载多个县级机构内容。行政区划不是机构，不允许把县区名称机械拼接为已确认公安局。

- institution：稳定ID、正式名称、别名、机构类型、多类别业务、省市县区划代码、层级、上级机构、存续状态、官方证据、核验日期。
- channel：机构ID、网站/政府栏目/官方账号/RSS/公开接口、域名和路径、官方归属证据、解析器、最近验证、可访问性、自动化可用性、更新节奏。
- discovery_task：任务地域、类别、查询、入口、发现时间、候选数量、失败原因、续跑位置。
- observation：任务和渠道ID、请求状态、解析候选数、相关数、重复数、新增数、发布时间缺失数、耗时、具体错误类别。
- document/event：原文链接、发布机构、发现渠道、原始标题、发布日期/抓取日期分别保存、正文/摘要证据、内容指纹、转载链、实体和事件归并。不得用检索任务名称替代实际发布机构。

目录状态：候选 → 官方归属核实 → 当前有效核实 → 渠道验证 → 接入 → 最近采集成功；另设人工渠道、暂停、失效。各状态必须按证据推进，不能直接按URL可访问判定有效。

## 3. 全国发现路径

交易机构：以国务院国资委、各省国资委、国家数据局及省级数据部门、科技部及各省科技部门、交易机构协会和交易所互链为起点，逐省扩展主要地市机构；名称变更、集团/子公司/分支、共用交易平台去重关联。产权、数据、技术类别分别建立缺口，不默认每省一定拥有三类独立交易所。没有找到标记未确认；确认不存在需单独证据。

公安：按官方县级以上行政区划基准建立发现任务，再根据各地机构设置确认公安厅、公安局、区分局、旗县公安局及实际发布渠道。省厅网站互链向市、县下钻，当地政府机构目录交叉核验。开发区、行业公安、兵团等不能由行政区划直接推断，作为补充机构任务。

全网发现：地域×机构类型×处置主题分层查询，官方机构发现与新闻发现使用不同查询。不限于原仓库，不只搜索已知机构。新报道提及的机构返回候选目录核验。站内定向检索必须限制真实域名/栏目并校验结果URL；全网结果按实际发布域名归属。候选结果不能因某引擎返回了不相关内容就停止其他检索路径。

当前已有官方基准为2024年县级以上行政区划，不称为2026年最新清单；上线覆盖率前必须补查2025—2026年变更。县区任务数量不等于公安机构数量。

## 4. 规模化采集

将发现任务和已核验渠道的定时增量采集分离，建立持久化队列、游标、失败重试与断点续跑。按域名限并发和请求速率，同站多个机关共享抓取结果。页面哈希、ETag/Last-Modified、发布时间窗口减少重复请求。高频重点渠道优先，低频渠道轮询；低频不等于永久排除。

不要让每个命名来源重复执行同一组全网查询。搜索供应商建立统一适配层，记录查询成功/失败/无相关结果，搜索预算与覆盖范围分别显示。现有搜索HTML解析不能作为唯一生产依赖；是否采用付费搜索API需先验证国内服务器可达性及样本质量，再报告实际费用和授权需求。

无独立网页、仅官方账号的渠道登记清楚；通过可合法访问的官方发布、政府转载和人工补充覆盖，自动化不可用明确显示，不虚报为已接入。

现有服务器约2.3GiB可用内存，可先采用受限并发的独立Python采集进程与SQLite单写入队列；依据实际压测决定是否升级数据库/队列，而不是直接并行请求数千网站。

## 5. 情报质量

覆盖广度与文章相关性独立：数据交易所可以进入机构目录，不代表其每条数据产品挂牌都属于虚拟货币处置。将涉案虚拟资产处置、罚没监管及合作机构业务等主题明确分类，资产与处置双维度判断。当前过滤强度需用真实相关/无关样本验证，不能靠放宽过滤凑入库数。

候选文章须保留原始证据。发布日期未知不填抓取日；历史回溯单独标记，不计为当天新发布。演示种子保持禁用。跨站转载按事件聚合但保留每个真实出处。规则金额不得跨币种相加。

## 6. 分阶段交付及验收

A. 修复当前采集：收集服务器HTTP/页面/候选/过滤诊断；修复网页适配、搜索回退、来源归属、失败详情；真实报道进入系统，旧网页不冒充新新闻。当前待服务器诊断输出。

B. 全国目录：31省×产权/数据/技术交易机构逐项完成调查，按省导出真实机构与渠道清单及缺口；公安按省市县下钻，覆盖所有区划发现任务。旧名录只作候选入口，不宣称当前资质。

C. 全国运行：队列化增量扫描、任务预算、断点续跑、数据来源溯源；接入覆盖矩阵，展示已登记/当前核实/已接入/最近成功/待人工/缺口。

D. 质量验收：已知真实历史报道回放检验漏检；正常增量周期观察；分别报告来源可用率、相关性准确率、日期准确率、去重结果和省份/机构层级覆盖。零相关结果与请求失败严格区分。不能用抽样通过宣称全国覆盖完成。

## 8. 2026-09-05 公共资源省级入口批量审计

新增研究脚本 `research/audit_channel_templates.py`，可按 `--kind` 对已有候选做公开HTTP首页审计、模板聚类和断点续跑。本轮只跑 `public_resource_platform`（31省区市及兵团，共32条候选）。同一工具今后可对产权交易所、数据交易所、技术交易所和公安机关候选使用，但那些类别尚未在本轮执行。
